# TanStack Start へのブログ移行設計

作成日: 2026-09-16

設計方針は会話で承認済み。
本文のレビュー後に、実装計画を作成する。
この文書は移行設計であり、実装や本番デプロイの実施記録ではない。

## 目的と範囲

Next.js 16 と Nextra 4 で構築したブログを、TanStack Start と Cloudflare Workers に移行する。
既存の機能、記事本文、公開 URL を維持し、見た目は本文中心のシンプルな 1 カラムに作り直す。
frontmatter の日付は、公開日を変えずに `YYYY-MM-DD` へ統一する。
記事の更新方法は、リポジトリ内の MDX を編集して再ビルドする方式を継続する。

対象はトップページ、記事一覧、記事本文、タグ別一覧、RSS、検索、テーマ切替、コード表示、読了時間、フォント、SNS リンク、Google Analytics とする。
CMS、認証、データベース、新しい記事分類の導入は含めない。
Cloudflare 内の現在の配信サービスとデプロイ設定はリポジトリから確認できていないため、切替作業の最初に実環境の構成を記録する。

## 現状の根拠

調査対象の基準コミットは `1e3e4f6`。
ソースコードと設定を確認した段階であり、既存サイトの HTML や本番レスポンスの比較は実装時に行う。

| 対象           | 現在の実装                                  | 移行上の扱い                                       |
| -------------- | ------------------------------------------- | -------------------------------------------------- |
| フレームワーク | Next.js 16.3.4、React 19.2.8                | Next.js の境界を Start に置換                      |
| コンテンツ     | トップページと記事 6 本の MDX               | 本文と既存 slug を維持                             |
| 記事取得       | `src/utils/get-posts.ts` の Nextra page map | 独立した記事データ層に置換                         |
| 共通 UI        | `nextra-theme-blog`                         | Base UI を基盤に Tailwind CSS で再実装             |
| 検索           | Pagefind、Nextra の Search                  | Pagefind を継続し検索 UI を置換                    |
| 索引生成       | `.next/server/app` から `public/_pagefind`  | Start の生成 HTML と配信成果物に変更               |
| フォント       | `next/font/google` の Noto Sans JP          | Next.js に依存しない自己配信に変更                 |
| 計測           | `@next/third-parties` の Google Analytics   | 同じ測定 ID で移植                                 |
| 開発環境       | Node.js 24.21.0、pnpm 11.26.0               | pnpm を継続し採用依存の互換性を確認                |
| 検証           | 自動テスト未設定                            | 記事データのテストと主要導線のブラウザテストを追加 |

記事にはローカル画像、外部画像、iframe、コードブロック、日本語見出しへのフラグメントリンクがある。
トップページにはアイコンの import と JSX があるため、Markdown だけを扱う変換では互換性を満たさない。
日付は `YYYY/MM/DD` と `YYYY-MM-DD` が混在している。
移行時にスラッシュ区切りの 4 本を変更し、全記事を `YYYY-MM-DD` に揃える。

## 採用方式

TanStack Start、TanStack Router、Vite、MDX、Base UI、Tailwind CSS、Cloudflare Workers を採用する。
汎用の UI プリミティブは `@base-ui/react` を基盤に `src/shared/components` へ実装する。
Workers 向けには `@cloudflare/vite-plugin` と Wrangler を使用する。
通常のルートコンポーネントと事前生成で構成し、実験的な React Server Components には依存しない。

移行方式として、既存の見た目まで再現する案と、機能を維持して見た目を作り直す案を比較した。
ユーザーは後者を選択した。
Nextra 固有のスタイル再現に依存せず、必要なブログ機能を個別のコンポーネントとして管理する。

Next.js は比較検証が終わるまで起動可能に保つ。
移行中は既存の `src/app` と Start の `src/routes` を併設し、開発コマンド、出力先、型チェック対象を分離する。
比較用の MDX コピーを置く場合は一時的なものとし、本文と frontmatter の一致を確認する。
日付書式の統一だけを許容する差分とし、変換前後で同じ公開日を表すことを検証する。
並行期間の記事変更は両方に反映し、切替後は `src/content` のみを編集元とする。

## モジュールの責務

以下は移行後の配置案であり、詳細なファイル分割は実装計画で定める。

| 配置                               | 責務                                                                             |
| ---------------------------------- | -------------------------------------------------------------------------------- |
| `src/content/home.mdx`             | トップページの本文と JSX                                                         |
| `src/content/posts/<slug>.mdx`     | 各記事の本文と frontmatter                                                       |
| `src/lib/posts.ts`                 | 記事情報の参照、日付順の一覧、タグ集計                                           |
| `src/lib/site.ts`                  | 公開 origin、サイト名、計測 ID などの共通設定                                    |
| `src/shared/components/`           | Base UI ベースのボタン、入力欄、ダイアログなどの汎用プリミティブ                 |
| `src/components/`                  | 汎用プリミティブを組み合わせたレイアウト、記事カード、検索、テーマ切替、MDX 表示 |
| `src/routes/`                      | URL と記事データを結び付けるルート、head、RSS                                    |
| `src/router.tsx`                   | ルーター生成とルートツリーの登録                                                 |
| `scripts/`                         | ビルド時の記事検証と生成処理                                                     |
| `vite.config.ts`、`wrangler.jsonc` | ビルド、事前生成、Workers の設定                                                 |

記事データ層は Nextra とルーターに依存しない。
一覧、タグ、RSS、事前生成対象の URL は同じ記事情報から導出する。
トップページは記事一覧や記事用 RSS に含めない。

`src/shared/components` は記事データ、Pagefind、計測、ルート固有の処理に依存しない。
Base UI の操作やアクセシビリティに関する機能を維持し、Tailwind CSS で共通スタイルを付ける。
検索ダイアログやテーマ切替などのブログ固有の振る舞いは `src/components` が担当する。
今回の画面で使用するプリミティブだけを実装する。

## MDX とデータの流れ

MDX はビルド時に `@mdx-js/rollup` でコンパイルする。
YAML frontmatter を扱うプラグインを追加し、タイトル、公開日、説明、タグ、著者を取り出す。
ビルド処理が正規化したメタデータと本文の import 対応表を生成し、Worker 実行時のファイル読み込みを不要にする。

記事一覧用のメタデータと、記事本文の遅延 import を分離する。
一覧ページを開くだけで全記事本文がクライアントに読み込まれる構成を避ける。
公開コンテンツだけを扱うため、記事表示のためだけにサーバー関数や TanStack Query を追加しない。

移行作業で既存の `YYYY/MM/DD` を `YYYY-MM-DD` へ変換し、MDX ファイル上の日付書式を統一する。
YAML パーサーによる Date 型への暗黙変換を避けるため、全記事で `date: "YYYY-MM-DD"` の引用符付き文字列として記述する。
移行後の検証はこの文字列書式と実在する日付を要求し、スラッシュ区切りや Date 型を受け入れない。
旧書式の対応は移行時の変換と比較に限定する。
記事順は公開日の降順とし、同日の場合は slug 順で安定させる。
RSS の日時は UTC で生成し、既存の配信結果と比較して日付が変わらないことを確認する。
必須項目の欠落、不正な日付、不正なタグの型、slug の重複は記事パス付きのビルドエラーとする。

見出し ID は現行 HTML と照合して既存リンクを維持する。
コードのハイライトはビルド時に処理し、コピー操作は小さなクライアントコンポーネントに分離する。
読了時間はビルド時に算出し、同じ本文に対して安定した値を返す。
既存の JSX、iframe、画像の URL、代替テキストを維持する。

## URL とレスポンス

| URL                  | Start のルート案          | 期待する動作                            |
| -------------------- | ------------------------- | --------------------------------------- |
| `/`                  | `index.tsx`               | プロフィールと既存リンクを表示          |
| `/posts`             | `posts.index.tsx`         | 日付降順の記事とタグ件数を表示          |
| `/posts/<slug>`      | `posts.$slug.tsx`         | 対応する MDX と記事情報を表示           |
| `/tags/<tag>`        | `tags.$tag.tsx`           | 該当記事とタグ名を表示                  |
| `/rss.xml`           | `rss[.]xml.ts`            | RSS XML と `application/rss+xml` を返す |
| 存在しない記事やパス | ルーターの not-found 処理 | HTTP 404 とホームへのリンクを表示       |

存在しないタグは現行の空一覧表示を維持し、HTTP 200 とする。
タグを URL に入れる際の符号化とルーター側の復号の責務を揃え、二重復号を避ける。
末尾スラッシュ、クエリ文字列、既存リダイレクトの実際の挙動は移行前に記録し、切替前の比較対象とする。

RSS は共通の記事情報から生成する。
タイトルや説明に含まれる XML の特殊文字をエスケープし、公開 origin は `https://blog.shusann01116.dev` に固定する。
プレビュー環境のホスト名を RSS や canonical に流用しない。

## 画面とメタデータ

共通レイアウトは、Home と Posts のナビゲーション、検索、テーマ切替、本文、SNS リンクを含むフッターで構成する。
画面幅に応じた余白と本文幅を持つ 1 カラムとし、見出し階層、リンク、コード、キーボードフォーカスを識別できるスタイルにする。
検索 UI はキーボードで操作でき、開閉時のフォーカスを管理する。
検索のダイアログ、入力欄、操作ボタンには `src/shared/components` のプリミティブを使用する。
Base UI の portal に合わせて重なり順を設定し、開閉、Escape キー、フォーカスの復帰を検証する。

テーマは初回に OS 設定を参照し、選択後はブラウザに保存する。
SSR と hydration の不一致、および初期表示時の不要なテーマ切替を検証する。
Noto Sans JP は必要なウェイトと日本語サブセットを自己配信し、本文の表示を妨げない読み込み設定にする。

Next.js の metadata は Start の route head に移し、ルートドキュメントに `HeadContent` と `Scripts` を置く。
現在のタイトル、説明、OG 情報などは Nextra の生成結果を含めて比較する。
canonical、robots、sitemap は現行配信の有無と内容を記録し、既存の公開動作を移植する。
存在しない SEO 機能の追加は今回の必須条件に含めない。
favicon と `/imgs/` の公開パスを維持する。

Google Analytics は既存の測定 ID を維持する。
初回表示とクライアント遷移の計測を確認し、二重送信を防ぐ。
プレビュー環境では本番への計測送信を無効にする。

## ビルドと Cloudflare 配信

ビルドは次の順序で行う。

1. MDX の frontmatter を検証し、メタデータと記事 import の対応表を生成する。
2. 記事と重複を除いたタグから、事前生成する URL を列挙する。
3. Vite で Start をビルドし、トップ、一覧、全記事、既存タグを事前生成する。
4. 生成 HTML を Pagefind に渡し、配信対象の静的アセットディレクトリ内に `_pagefind` を出力する。
5. 全対象 HTML と索引の存在を確認してから、静的アセットと Worker をデプロイする。

Pagefind の入力と出力は、採用したプラグインの実際のビルド成果物に合わせて固定する。
ビルド後に `public` へ索引を出力するだけでは、既にコピー済みの配信成果物へ反映されない可能性があるため、完成した配信対象に出力する。
記事本文とタイトルを検索対象とし、ナビゲーションや一覧による同じ記事の重複を避ける。
日本語の検索結果と記事への遷移を確認する。

既知の公開ページは生成 HTML を静的アセットとして配信し、RSS と生成対象外の URL は Worker で処理する。
未知の URL を一律に SPA の HTML へフォールバックさせず、アプリが 404 または空のタグ一覧を返せる設定にする。
採用する Vite プラグインと事前生成の組み合わせ、アセットの優先順位、Worker の経由条件は、最初の最小構成で検証する。
この組み合わせは本設計時点では実行検証していない。

生成ページと索引は同じビルドから配信する。
コンテンツ更新は再ビルドと再デプロイで反映し、ハッシュのない HTML や索引入口に無期限のキャッシュを設定しない。
ISR、KV、D1、R2 は今回の構成に追加しない。

## エラー処理

コンテンツの不正や既知ページの事前生成失敗はビルドを失敗させ、不完全な成果物を公開しない。
存在しない記事は 404 とし、本文の読み込み失敗などの予期しないエラーはルートのエラー画面で扱う。
検索モジュールや索引の読み込み失敗は検索部分に限定して表示し、再試行できるようにする。
検索に失敗してもナビゲーションと本文閲覧は継続できる。

## 検証と受け入れ条件

既存アプリを起動し、公開 URL、HTTP ステータス、リダイレクト、head、見出し ID、記事順、タグ件数、RSS の基準値を保存する。
現在のタグは `blog` と `book` であり、記事を追加した場合は自動的に検証対象へ反映する。
コードから推定した挙動と基準値が異なる場合は、その差を記録して期待動作を調整する。

| 検証対象   | 合格条件                                                                                       |
| ---------- | ---------------------------------------------------------------------------------------------- |
| 記事データ | 6 本の本文、既存 slug、日付以外の frontmatter を維持し、公開日、日付順、タグ件数が一致         |
| 日付統一   | 全記事の date が引用符付き `YYYY-MM-DD` となり、旧書式からの変換で公開日が変わらない           |
| データ検証 | 不正日付、旧日付書式、Date 型、必須項目欠落、重複 slug を検出                                  |
| UI 基盤    | 汎用プリミティブが Base UI ベースで `src/shared/components` にあり、ブログ固有処理に依存しない |
| HTML       | JavaScript 実行前のレスポンスに本文とページ固有のメタデータが存在                              |
| リンク     | 直接アクセス、再読み込み、クライアント遷移、戻る、進むが動作                                   |
| MDX        | 日本語アンカー、画像、iframe、JSX、コード表示とコピーが動作                                    |
| RSS        | 公開 URL と日付が一致し、特殊文字を含む XML が構文解析できる                                   |
| 404 とタグ | 不明記事は HTTP 404、不明タグは空一覧の HTTP 200                                               |
| 検索       | 日本語検索から正しい記事へ移動でき、配信環境で索引が取得できる                                 |
| テーマ     | 保存した選択を維持し、hydration エラーが発生しない                                             |
| 計測       | 本番のページ表示を重複なく計測し、プレビューから送信しない                                     |
| ビルド     | 型チェック、lint、本番ビルド、事前生成、索引生成に成功                                         |
| Cloudflare | 実際のプレビュー配信で静的ページ、RSS、404、索引を確認                                         |

単体テストは日付書式の検証、変換前後の公開日の一致、並び順、タグ集計、frontmatter 検証、RSS の XML エスケープに集中する。
ブラウザテストは代表的な記事、トップ、一覧、タグ、検索、テーマ切替を対象とする。
変更前後で見た目の一致は要求せず、モバイルとデスクトップで本文の可読性と操作性を確認する。

## 移行順序と切り戻し

1. 現行の動作と Cloudflare の配信設定を記録する。
2. Next.js を残して Start と Workers の最小構成を用意し、事前生成と配信を確認する。
3. 記事データ層と MDX を移植し、frontmatter の日付を統一して、一覧、記事、タグ、RSS を接続する。
4. Base UI を基盤とする汎用プリミティブを `src/shared/components` に実装し、共通 UI、検索、テーマ、フォント、計測、メタデータを接続する。
5. 比較テストと Cloudflare のプレビュー検証を完了する。
6. 公開ドメインを新しい配信へ切り替え、主要 URL を再確認する。
7. 切り戻し可能な旧成果物を残し、不要な Next.js と Nextra の依存や設定を除去する。

切替前に、旧デプロイの識別子、対象コミット、カスタムドメインの割当、Worker route または DNS の設定、元に戻す操作を記録する。
現在の配信が Workers か Pages かに応じて、復旧操作を具体化する。
主要 URL の 5xx、記事の欠落、RSS や検索の配信失敗が切替後に確認された場合は、記録した設定で旧配信に戻す。
切替と同時に記事の内容を変更せず、新旧どちらに戻しても同じ記事が読める状態を保つ。

依存除去には `next`、`@next/third-parties`、`nextra`、`nextra-theme-blog`、Next.js 用設定、型生成物の参照、oxlint の `nextjs` プラグインを含める。
`sharp` は移行後の画像処理で使用しないことを確認してから削除する。
`CLAUDE.md` の App Router と Server Components を前提にした説明、開発コマンド、生成物の ignore 設定も更新する。
